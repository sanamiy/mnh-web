今夜のハッカソン向け

BERTのしくみと使い方

今夜のハッカソンで使う BERT について、まず「何ができるか」を紹介し、そのあと仕組みを順に深掘りします。専門用語は、出てきたところで説明します。

全体像：BERT で何ができるか

BERT とは

BERT は、2018年に Google が発表した言語モデルです。文章を読んで、その意味を数値の並び（ベクトル）で表すのが得意です。

もう少し具体的に言うと、BERT は文章を単語より細かい単位（トークン）に区切り、トークンごとに高次元のベクトル（BERT の場合は768個の数値の並び）を出力します。このベクトルには前後の文脈が反映されていて、同じ「かける」でも「電話をかける」と「眼鏡をかける」では違うベクトルになります。

ChatGPT や Claude のような LLM（大規模言語モデル）と同じ Transformer という技術をもとにしていますが、役割が違います。LLM が文章を書くモデルなのに対して、BERT は文章を読んで理解するモデルです。

BERTLLM（GPT、Claude など）
得意なこと文章を読んで理解する（分類・検索・抽出）文章を書く（対話・要約・コード生成）
出力ラベル、スコア、ベクトル文章
大きさ約1.1億パラメータ。手元の PC でも動く数十億〜数千億パラメータ。多くは GPU や API が必要
速さ・コスト速い・安い比較的重い

文章は書けませんが、そのかわり大量の文章を速く安く読めるのが BERT の強みです。そのため、検索や分類のように「たくさん読んで判断する」部分で、今も広く使われています。

BERT でできること

BERT の使い方は、大きく5つに分けられます。①〜③は1つの文を処理するもの、④と⑤は文と文を比べるものです。

使い方何をするか例
① 文の分類文全体にラベルを1つ付ける感情分析（このレビューはポジティブか）、スパム判定、有害な投稿の検出、問い合わせの振り分け
② トークン分類文中の単語一つひとつにラベルを付ける人名・地名・会社名の抽出、個人情報の自動マスキング
③ 穴埋め隠した単語を、前後の文脈から予測する文脈に合う単語の予測、誤字・変換ミスの検出
④ 文埋め込み文を1本のベクトルにして、意味の近さを測る意味検索、RAG（検索した文書を LLM に渡して回答させる仕組み）の検索部分、似た文書のレコメンド、アンケートの話題分け
⑤ 文ペアの判定2つの文の関係をスコアにする検索結果の並べ替え、質問と回答がかみ合っているかの判定

5つとも、使っている BERT 本体は同じです。本体の出力の上に付ける小さな部品（ヘッド）を変えることで、使い分けています。

BERT を使った埋め込みモデル

5つのうち④文埋め込みには、専用の埋め込みモデルを使います。BERT が出すトークンごとのベクトルを1本にまとめ、文全体の意味を表すように追加で学習したモデルです。文と文の意味の近さをベクトルで比べられるので、検索や RAG によく使われています。代表的なものに、Sentence-BERT や、日本語向けの ruri-v3 などがあります。

多くの用途では、すでに部品まで学習済みのモデルが公開されているので、自分で学習させなくてもすぐに試せます。このあと、アイデア例と実際に使える公開モデルを紹介し、それぞれの仕組みは後半で詳しく説明します。

用途別のおすすめモデル

上の表のほかに、性能と使いやすさの面でおすすめできる日本語モデルを用途ごとにまとめました（2026年10月時点）。2025年以降は、日本語でも ModernBERT（BERT を高速化し、長い入力に対応させた改良版）をもとにしたモデルが中心になっていて、ここで紹介するモデルの多くもその日本語版を土台にしています。

④ 文埋め込み：ruri-v3 のサイズを選ぶ

日本語の埋め込みモデルでは、名古屋大学の ruri-v3 が性能・ライセンス（Apache 2.0）・扱いやすさのバランスで最も使いやすい選択肢です。4つのサイズがあり、小さいものでも性能の落ち方はわずかです。スコアは日本語の埋め込みベンチマーク JMTEB の平均で、モデルカードの値です。

モデルパラメータ数JMTEB向いている場面

cl-nagoya/ruri-v3-70m7,000万75.48速さと精度のバランス
cl-nagoya/ruri-v3-130m1.3億76.55速さと精度のバランス

④ 文埋め込み：さらに軽さを優先するなら

個人開発者の六花牡丹さん（RikkaBotan）が公開している RikkaBotan/stable-static-embedding-fast-retrieval-mrl-ja は、約1,700万パラメータの非常に軽い日本語の埋め込みモデルです（Apache 2.0）。ruri-v3 のいちばん小さいサイズよりもさらに小さく、CPU だけで大量の文書を速くベクトル化したいときに向いています。日本語と英語の両方に対応した版もあります。

Transformer を使わず、各トークンのベクトルを平均して文のベクトルを作る「静的埋め込み」という方式なので、文脈を見る ruri-v3 などと比べると精度は下がりやすい点に注意してください。読み込み時に trust_remote_code=True の指定が必要です。

⑤ 文ペアの判定：軽いリランカーを使うなら

上の表の ruri-v3-reranker-310m は精度重視のモデルです。手元の PC で速く動かしたいときは、個人開発者の hotchpotch さんが公開している japanese-reranker v2 シリーズが使えます。ruri-v3 の土台モデルをもとにしていて、tiny・xsmall・small・base の4サイズがあります。いちばん小さい tiny は約3,000万パラメータで、CPU や Mac でも実用的な速さで動きます（MIT ライセンス）。

自分のデータで追加学習（ファインチューニング）するなら

分類などを自分のデータで学習させたいときは、SB Intuitions の ModernBERT-Ja（sbintuitions/modernbert-ja-310m など、30M〜310M の4サイズ、MIT ライセンス）が土台として使えます。日本語と英語の約4.1兆トークンで学習されていて、最大8,192トークンの長い文章を扱えます。ただし、トークンの区切り方の都合で、②トークン分類（固有表現抽出など）は苦手とされています。②トークン分類を自分で学習させるなら、MeCab で単語に区切る東北大学の BERT（tohoku-nlp/bert-base-japanese-v3）のほうが向いています。

制約と、LLM との役割分担

BERT の制約

  • 文章の生成はできない：文章を作る部分は LLM に任せる
  • 入力の長さに上限がある：元の BERT は512トークン（トークンは文章を区切った単位）まで。長い文書は分割して扱う（ModernBERT 系はもっと長い入力を扱える）
  • 学習データと違う分野には弱いことがある：専門用語の多い文章などでは精度が落ちることがある
  • 細かい意味の違いに弱いことがある：④文埋め込みでは、否定の有無や語順の違いがベクトルの差に出にくいことがある

LLM と比べた BERT の利点

  • 軽い：パラメータ数が LLM より桁違いに少なく、手元の PC でも動く
  • 速い・安い：大量のデータを短時間で処理でき、API の利用料もかからない
  • 出力が安定している：同じ入力には同じ出力を返す

LLM との組み合わせ方

BERT と LLM は、どちらか一方を選ぶものではなく、組み合わせて使うのが基本です。大量の文章を読んで「探す」「分ける」「抜き出す」作業は、速くて安い BERT が担当します。その結果を受け取って文章を書く作業は、LLM が担当します。

たとえば RAG のチャットボットでは、BERT 系の埋め込みモデルで質問に関係する文書を探し、見つかった文書をもとに LLM が回答を書きます。個人情報を含む文章を LLM に送る前に、BERT で人名や住所を見つけて伏せておく、という使い方もできます。

しくみを深掘りする

ここからは、BERT がなぜこれらのことをできるのかを、文章が数値になるところから順に説明します。

言語モデルはテキストをどう扱うか

トークン化：文章を小さな単位に区切る

モデルは文字列をそのまま扱えません。まず文章をトークンという単位に区切ります。トークンは単語とは限らず、単語より細かい断片（サブワード）になることもあります。

「自然言語処理は楽しい」 → ["自然", "言語", "処理", "は", "楽しい"]

モデルごとに語彙（扱えるトークンの一覧、数万種類程度）が決まっていて、各トークンには ID 番号が振られています。

埋め込み：トークンをベクトルにする

ID 番号のままでは計算できないので、各トークンを数百次元の数値の並び（ベクトル）に変換します。この変換を埋め込み（embedding）と呼びます。BERT の場合は、1トークンあたり768個の数値です。

ただし、この段階のベクトルは「そのトークン単体」の意味しか表していません。辞書を引くのと同じで、文脈は考慮されません。下の図では、ベクトルの各数値の大きさを色の濃さで表しています。

同じ「かける」でも、「電話をかける」と「眼鏡をかける」では意味が違います。文脈に応じてベクトルを変える仕組みが、次に説明する Attention です。

Attention と Transformer

Attention：周りのトークンから情報を集める

Attention は、各トークンが「文中の他のトークンをどれだけ参考にするか」の割合を計算し、その割合に応じて他のトークンの情報を自分のベクトルに混ぜ込む仕組みです。

どのトークンをどれだけ参照するかは固定ではなく、トークン同士の組み合わせから毎回計算されます。その計算方法そのものを、大量のテキストから学習します。文中のトークン同士で参照し合うので、Self-Attention（自己注意）とも呼ばれます。

位置の情報を加える

Attention はそれだけではトークンの順番を区別できません。「犬が猫を追う」と「猫が犬を追う」が同じに見えてしまいます。そこで、各トークンのベクトルに「何番目のトークンか」を表す位置の情報を加えてから Attention に通します。

層を重ねる：Transformer

「Attention で周りから情報を集める → 各トークンのベクトルを個別に変換する」を1つの層として、これを何層も積み重ねます。層を重ねるほど、より複雑な文脈を反映したベクトルになっていきます。下の図では、下から上へ処理が進みます。

この構造が、2017年に Google が発表した Transformer です（論文「Attention Is All You Need」）。BERT も GPT も Claude も、現在のほとんどの言語モデルはこれをもとにしています。

Encoder と Decoder

本来の意味：ベクトルにする側と、ベクトルから戻す側

一般的な意味では、Encoder は人間が扱えるもの（文章や画像）をベクトルに変換する部分、Decoder はベクトルから人間が扱えるものを作り出す部分です。

元の Transformer は翻訳のためのモデルで、まさにこの2つの部分で構成されていました。Encoder が日本語の文を読んでベクトルにし、Decoder がそのベクトルを参照しながら英語の文を1トークンずつ生成します。下の図の下段は、このあと説明する Decoder-only モデルが文章を生成する様子です。

Encoder-only / Decoder-only では、この説明がずれる

その後、どちらか一方の部分だけを使うモデルが主流になりました。BERT は Encoder-only、GPT や Claude は Decoder-only です。

ところが、これらを「ベクトルにする側 / ベクトルから戻す側」で説明しようとすると、うまくいきません。

  • Decoder-only も入力をベクトルにしている：GPT も入力をトークンのベクトルにして層に通しています。1つのモデルの中で「読む」と「書く」の両方をしています
  • Encoder-only も人間が読める答えを出せる：BERT も、前半で紹介した「ヘッド」を付ければ「ポジティブ」のようなラベルや単語を出力できます

つまり Encoder-only / Decoder-only という名前は、元の Transformer の Encoder 側と Decoder 側、どちらの作りを受け継いでいるかを表しています。作りの違いは、主に Attention で参照できる範囲です。

実際の違い：Attention で参照できる範囲

Encoder は、各トークンが文中のすべてのトークン（前も後ろも）を参照できます。Decoder は、各トークンが自分より前のトークンしか参照できません。後ろを参照できないようにすることを、マスクと呼びます。

Decoder が後ろを参照できないのは、「次のトークンを予測する」ことで学習と生成をするためです。予測の答えになる後ろのトークンが見えていると、学習が成り立ちません。逆に言えば、この制限があるからこそ、次のトークンを予測しては付け足すことを繰り返して、1トークンずつ文章を生成できます。

Encoder-only（BERT など）Decoder-only（GPT、Claude など）
参照できる範囲前後すべて（双方向）自分より前だけ（一方向）
出力入力全体を読んで、各トークンのベクトルを一度に出す次のトークンを予測して付け足すことを繰り返す
得意なこと文章の理解（分類、検索、抽出）文章の生成（対話、要約、コード）

BERT のしくみ

構造

BERT（Bidirectional Encoder Representations from Transformers）は、2018年に Google が発表した Encoder-only のモデルです。名前の「Bidirectional」は、Attention が双方向であることを指しています。

層の数12層（Base サイズ。Large は24層）
ベクトルの次元1トークンあたり768
パラメータ数約1.1億（GPT 系の LLM と比べて桁違いに小さい）
入力できる長さ512トークンまで

特殊トークン

BERT への入力には、文章のトークンに加えて、特別な役割を持つトークンを入れます。

トークン役割
[CLS]入力の先頭に必ず置く。文全体を代表するベクトルとして使われる
[SEP]文の区切り。2つの文を入力するときは、文の間と最後に置く
[MASK]「ここに入る単語を当てて」という穴埋めの印

[CLS] 自体には意味がありません。そのため Attention を通じて文中の全トークンから情報を集め、層を重ねるうちに文全体の要約のようなベクトルになります。

事前学習：穴埋め問題（Masked Language Model）

BERT は、大量のテキスト（Wikipedia や書籍）を使って、次の穴埋め問題を解きながら学習します。

  1. 文中のトークンの 15% をランダムに選び、[MASK] に置き換える（正確には、選んだうちの80%を [MASK]、10%をランダムな別のトークンにし、10%はそのまま残す）
  2. BERT に通して、隠した位置のベクトルから元のトークンを予測させる
  3. 正解のトークンの確率が上がるように、モデル全体の重みを少しずつ調整する

この学習方法を Masked Language Model（MLM）と呼びます。正解は元の文章そのものなので、人手でラベルを付ける必要がなく、いくらでも学習データを用意できます。

なぜ穴埋めで賢くなるのか[MASK] に入る単語を当てるには、周りの文脈を理解している必要があります。この問題を大量に解くうちに、BERT は「文脈を反映したベクトルを作る」能力を身につけます。穴埋めは練習問題で、本当の目的は良いベクトルを作れるようになることです。

（元の BERT は、2つの文が本当に連続しているかを当てる課題（NSP: Next Sentence Prediction）も同時に学習していました。ただし後の研究で効果が小さいことがわかり、最近のモデルでは使われていません。）

BERT の出力

学習済みの BERT に文を入れると、トークンごとに、文脈を反映したベクトルが出力されます。最初にトークンをベクトルにした段階とは違い、「電話をかける」の「かける」と「眼鏡をかける」の「かける」は、ここでは別のベクトルになります。

ヘッドとファインチューニング

BERT の出力はベクトルの列なので、このままでは「この文はポジティブか」のような答えは出てきません。そこで、出力の上に目的に合わせた小さな層を付けます。この層をヘッドと呼びます（多くは1層の線形変換です）。事前学習で使った「穴埋めヘッド」もその一つです。

文章 → [BERT 本体] → トークンごとのベクトル → [ヘッド] → 答え（ラベル・スコアなど）

ヘッドを付けて、目的のタスクの正解付きデータで追加学習することをファインチューニングと呼びます。BERT 本体の重みも少しずつ調整されます。事前学習で文脈を理解する力がついているので、数千件程度のデータでも高い精度が出やすいのが特徴です。

今夜は、自分でファインチューニングしなくても大丈夫です。ファインチューニング済みのモデルが Hugging Face（機械学習モデルの共有サイト）に多数公開されていて、ダウンロードしてすぐ使えます。

BERT 系のモデル

BERT の発表後、同じ Encoder-only の構造のまま、学習データや学習方法を改良したモデルが多く登場しました。この資料では、これらをまとめて「BERT 系」と呼びます。使い方は BERT と同じなので、以降の説明はすべて BERT 系のモデルに当てはまります。

モデルBERT からの主な違い
RoBERTa（2019年、Meta）より多くのデータで長く学習。NSP をやめるなど学習方法を改良
XLM-RoBERTa（2019年、Meta）RoBERTa を約100言語のテキストで学習した多言語版
ModernBERT（2024年）最近の LLM で使われている技術を取り入れ、高速化と長い入力（8192トークン）への対応を実現

5つの使い方のしくみ

最初に紹介した5つの使い方が、それぞれどう動いているかを説明します。どの使い方も、BERT の出力のどこに、どんなヘッドを付けるかの違いです。

① 文の分類　② トークン分類

① 文の分類は、[CLS] のベクトルにヘッドを付けて、文全体にラベルを1つ付けます。② トークン分類は、各トークンのベクトルにヘッドを付けて、トークンごとにラベルを付けます。

① 文の分類の用途は、感情分析、スパム判定、有害投稿の検出、問い合わせの振り分けなどです。出力できるラベルの種類はモデルの学習時に決まっているので、公開モデルを使うときは、どんなラベルで学習されたかをモデルカード（Hugging Face の説明ページ）で確認してください。

② トークン分類の代表例は固有表現抽出（NER: Named Entity Recognition）で、文中の人名・地名・組織名などを見つけます。実際には「人名の始まり」「人名の続き」のようにラベルを分けて付けるので、複数のトークンにまたがる名前もひとまとまりで取り出せます。見つけた範囲を伏せ字にすれば、個人情報マスキングになります。

③ 穴埋め

事前学習で使った穴埋めヘッドを、そのまま使います。[MASK] の位置に入るトークンの確率が、語彙全体について得られます。

応用：不自然な単語の検出　文中のトークンを1つずつ隠して、元のトークンの確率を調べます。確率が極端に低いトークンは「この文脈では不自然」なので、誤字や変換ミスの候補になります。

④ 文埋め込み

文を1本のベクトルにして、ベクトル同士の近さで文の意味の近さを測ります。意味の近い文はベクトル空間の中で近くに、無関係な文は遠くに配置されます。下の図は、実際には数百次元あるベクトルを、説明のため2次元に描いたイメージです。

近さの測り方：2本のベクトルの向きがどれだけそろっているかを測るコサイン類似度がよく使われます。1に近いほど似ていて、0に近いほど無関係です。

素の BERT では不十分な理由：BERT の出力（トークンごとのベクトル）を平均して1本にすることはできます。ただ、BERT は穴埋めのために学習したモデルなので、そのベクトルが「文の意味の近さ」をうまく表すとは限りません。

対照学習で「埋め込みモデル」にする：そこで、「意味の近い文のペア（質問と答え、言い換えなど）はベクトルが近くなり、無関係な文は遠くなる」ように追加学習します。この学習方法を対照学習、こうして作ったモデルを埋め込みモデルと呼びます。2019年の Sentence-BERT が代表的な手法です。

用途：意味検索、RAG（質問に関係する文書を検索して LLM に渡し、回答させる仕組み）の検索部分、類似文・重複の検出、レコメンドなど。ベクトルを k-means などで似たもの同士に分ければ（クラスタリング）、アンケートやレビューを話題ごとに整理することもできます。

⑤ 文ペアの判定

2つの文を [CLS] 文A [SEP] 文B [SEP] の形でつなげて1回で入力し、[CLS] のベクトルからスコアを出します。④文埋め込みとの違いは、2つの文を別々に処理するか、まとめて処理するかです。

④文埋め込みのように文を別々にベクトル化する方式を Bi-encoder、⑤文ペアの判定のようにつなげて入力する方式を Cross-encoder と呼びます。Cross-encoder は2つの文のトークン同士が直接参照し合えるので精度が高い一方、ペアごとに BERT を通す必要があり、文書を事前に計算しておけません。

そこで実際の検索システムでは、2つを組み合わせた二段構成がよく使われます。⑤文ペアの判定のモデルで候補を並べ替える役割をリランキング、そのためのモデルをリランカーと呼びます。

同じ Cross-encoder の仕組みで、「2つの文が矛盾していないか」「質問と回答がかみ合っているか」といった判定にも使えます。
